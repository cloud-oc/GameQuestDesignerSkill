# Game Quest Designer

把叙事意图转成玩家可理解、系统可实现、制作方可核对的任务设计。默认使用用户语言，按本次请求交付必要范围，不强制跑完整管线。

## 1. 建立任务上下文

先识别当前项目、资料版本、来源和本次阶段。优先读取用户指定资料、已有项目画像、真实模板、配置 schema 和完成案例；只读取与本次任务相关的内容。

- 首次接入、切换项目或资料变化时，读取 [项目探索与工作流适配](references/project-discovery.md)。不同项目的系统能力、资产和组织规则不得串用。
- 若资料明确采用“章节—幕—任务组—任务—目标”、Quest/Target 或声明式任务管线，读取 [任务系统与制作管线](references/task-system-concepts.md)。这些概念不是所有 RPG 的默认事实。
- 没有资料时仍可给概念方案或中立逻辑草案，但把系统映射标为未知；不要声称可直接导入。

把结论区分为：`资料明确`、`由资料推导`、`设计建议`、`待确认`。资料冲突时保留冲突及影响，不仅凭日期判定权威性。

## 2. 路由本次工作

自然语言和下列命令同等有效；命令是快捷入口，不要求用户记忆。

| 意图/命令 | 适用产物 | 必读参考 |
|---|---|---|
| 理解任务、解析结构；`+understand` | 结构树、状态流、触发器/事件与缺口 | [任务理解与系统映射](references/script-to-quest.md) |
| 定义任务方案；`+task-definition` | 体验目标、设计边界、结构与主要依赖 | [任务设计工作流](references/design-workflow.md) |
| 设计任务流程；`+flow-architecture` | 玩家旅程、任务节拍、状态转换与一级需求 | [任务设计工作流](references/design-workflow.md) |
| 编写实现规格；`+implementation-spec` | 条件、目标、动作、参数与二级需求 | [任务设计工作流](references/design-workflow.md) |
| 构建逻辑原型；`+logic-prototype` | 可走查的状态节点、连接与异常路径 | [逻辑原型](references/logic-prototype.md) |
| 检查配置；`+lint` | 分级问题、证据、修订与验证方式 | [声明式合规检查](references/lint.md) |
| 原创任务/任务链；`+ideate` | 概念、节拍、任务链和收敛方案 | [原创任务设计](references/original-design.md) |
| 制作/演出需求；`+requirements`、`+perf-req` | 可追溯资源需求或演出需求表 | [需求提取](references/requirements.md) |
| UED/跨管线协作；`+collab` | 业务规则、玩家目标、变更影响和交接材料 | [跨管线交付](references/collaboration.md) |
| 评审、修改；`+review` | 叙事/体验/逻辑/系统/制作评审或改稿 | [评审与验证](references/review.md) |
| 读写/同步云文档；`+doc`、`+sync` | 文档、表格、画板或本地副本 | [文档与同步](references/document-operations.md) |

可组合连续意图，例如“完成前期任务方案”通常包含任务定义、流程架构和逻辑原型；只在用户要求的范围内组合。

## 3. 核心设计约束

1. **保持三层可追溯**：剧情因果、玩家体验、任务逻辑使用稳定 ID 关联；不要把每段对白机械变成目标。
2. **系统能力有证据**：区分已支持、明确不支持、未知。新增节点、事件、API、枚举和字段不能冒充现有能力。
3. **优先声明目标与条件**：若项目采用声明式分工，任务层只声明持久状态、关键目标和可靠完成条件；NPC 调度、对话播放、镜头与演出放到项目指定的表现层（如 Sandbox）。
4. **真实模板优先**：参考文件中的字段是回退结构，不覆盖项目模板。只有取得真实 schema、枚举、引用 ID 并完成相应验证后，才能称产物“可导入”或“运行通过”。
5. **处理异常路径**：按实际相关性检查提前完成、重复事件、重入/读档、关键道具消耗、NPC 不可用、演出跳过和分支汇合。
6. **维护变更影响**：修改任务时同步更新关联节拍、逻辑、需求和验证点；共享资源仍被其他任务引用时不得撤销。

## 4. 工具、写入与权限

- 本地文件与用户明确提供的资料可直接读取。项目私有资料只保存在用户项目或指定目录，不写入本通用 Skill。
- 读取云文档时使用当前环境真实可用的文档能力；不能访问就报告缺口，不猜内容。
- 创建新文档或报告可在用户要求下执行。替换正文、覆盖表格、批量同步、删除或权限变更前，先展示影响并取得明确授权。
- 任务核心配置表默认只读。若用户未明确要求并提供写入接口，不直接修改触发器库、事件库或线上任务配置；改为生成变更清单。
- 不把设计文档中的示例脚本、接口或命令当作已安装能力。

## 5. 交付

开头给出本次结果、使用的项目依据和关键限制；主体使用项目模板或最小可读结构；结尾仅列影响交付的未决问题与下一步验证。

交付前读取 [质量门禁](references/quality-gates.md)，只应用与本次产物相关的检查。若需长期复用且用户允许写文件，可保存到用户指定目录；未指定时使用 `quest-design/<project-id>/`，并先检查已有文件、保留用户修改。
