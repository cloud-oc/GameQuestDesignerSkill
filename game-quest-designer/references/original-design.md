# 原创任务与任务链

从用户给出的世界观、角色关系、区域特点、可用玩法和制作预算提炼设计约束。没有资料时可以创造临时设定，但应单独标为设计提案。不要默认开放世界、战斗、多结局或特定引擎。

先找到一个能转化为玩家行动的矛盾：谁想要什么、为什么受阻、玩家为什么参与、行动怎样改变局面。让地点、角色和机制影响玩法，避免仅替换地名与 NPC 的通用跑腿任务。

用户要方向时提供少量真正不同的概念；用户要完整任务时选取合理方案直接展开，说明必要假设，不强制增加概念确认环节。

按项目模板展开适用内容：

- 名称、一句话概念、任务类型及在主线或区域中的作用。
- 触发契机、玩家动机和角色动机；区分玩家有理由参与与 NPC 有理由委托。
- 关键节拍、玩家行为、玩法变化、信息揭示和反馈。
- 转折如何由前文铺垫；选择只在有意义时加入，说明信息、代价与可感知后果。
- 结束状态、奖励或世界变化，以及后续任务的依赖。
- 复用资产和玩法、新增需求、未知系统能力及可缩减方案。

任务链应解释前后因果、解锁条件、共享角色或状态，以及中途退出再返回的体验。不要为了数量把一个目标拆成多个任务。

检查长距离移动、重复交互和对白密度是否有体验目的；允许有意设计的平静段落，不机械要求每步有战斗或转折。时长、数量和资源成本如无实际依据，标为设计估计或目标，不能当测试数据。

概念确定后，按 [剧本拆解与系统映射](script-to-quest.md) 将完整设计落为可追溯流程，再按 [需求提取](requirements.md) 汇总制作依赖。
