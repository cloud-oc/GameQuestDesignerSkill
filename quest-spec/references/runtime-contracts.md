# 运行时行为与开发交接

用于涉及存档、共享世界对象、异步事件、联机或版本更新的任务实现规格。这里描述期望行为，不预设引擎、API 或数据字段。

## 状态所有权

为相关状态定义：含义、合法值、读写方、作用域、持久化位置、有效期、变更条件、恢复来源。区分：

- 玩家/队伍/世界任务进度；
- 任务实例中的局部计数；
- 世界持久事实（桥已修复、角色死亡）；
- 表现中的临时状态（当前对白、镜头、临时 NPC）。

条件引用世界事实时考虑任务接取前已成立的情况。临时表现对象的消失不应清除持久进度。任务目标需要实体时，说明稳定标识如何解析为当前加载实例。

## 状态转换与副作用

每个关键转换说明：旧状态、守卫条件、输入事件及来源、重复判定、持久变化、外部副作用和恢复办法。

对“交付物品并发奖”，分别追问：背包校验与消耗间被改变怎么办；消耗完成但奖励未到怎么办；奖励已到但完成确认丢失怎么办。依据真实项目机制确定事务、幂等请求或补偿方案，不凭空保证“恰好一次”。

延迟事件须核对任务实例与当前阶段。失败重试开启新实例后，旧实例的击杀/对白回执不可推进新实例。没有可区分实例的机制时，明确替代方案与限制。

进入状态时订阅事件、退出时解除或屏蔽旧监听的语义需明确。不要只用事件驱动推进而漏掉状态恢复时重新计算已满足条件。

## 存档、重入与场景加载

按持久检查点定义恢复结果：应显示的目标、NPC 与道具状态、已完成副作用、需重建表现、是否允许重新播放。

场景卸载与重载后，根据持久状态恢复表现。剧情跳过是完成表现、取消表现还是只跳镜头，必须明确；也要说明跳过后玩家获得的必要信息如何补充。

共享 NPC 涉及多个任务时，定义可用性判断、冲突优先级、等待/替代路径及释放条件；不要由每个任务直接互相覆盖角色状态。

## 联机（仅适用项目）

明确队伍共享进度还是个人进度、参与与贡献资格、事件权威来源、掉线重入和中途加入的追认范围。主机完成不自动等于所有成员领取奖励。

同一互动同时由两名玩家触发时，定义竞争结果与各自反馈。任务展示与真实结算应分别验证。

## 内容更新（仅涉及旧存档时）

任务或节点 ID 变更、目标被删除、奖励调整时，列出受影响存档阶段和迁移结果。稳定 ID 不复用为不同语义。

先检查现有迁移策略，再提出迁移、保留旧版本或重置补偿等选择。给出旧版本存档加载后的预期状态，不将更新配置文件等同于迁移完成。

## 开发验收记录

按项目格式记录：规则 ID、输入及前置状态、权威状态变化、副作用、失败反馈、恢复预期、对应测试 ID。未决接口写明由哪项能力缺口阻塞，不编造程序负责人。
