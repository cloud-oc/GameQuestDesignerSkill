# RPG 任务设计决策

用于完整任务、任务链或已有方案改进。先选与项目相关的问题，不强制每条任务使用所有机制。

## 从灵感种子推导可制作任务

不要从“做一个调查任务/护送任务”开始套结构。按以下因果逐步收敛，缺少项目资料时将结论标为临时提案：

1. **角色或世界矛盾**：谁想改变什么，谁或什么阻止它，为什么此刻必须处理。
2. **玩家承诺**：玩家接受内容后，预期会判断、发现、保护、改变或承担什么，而不只是获得奖励。
3. **可操作动词**：用项目已支持的观察、询问、比较、追踪、交易、潜入、战斗等行为兑现承诺。
4. **信息与反馈**：每个关键行动前玩家知道什么，行动后系统怎样让其理解结果和下一步。
5. **状态变化**：任务结束后关系、认知、地点、资源或世界事实发生何种可感知变化。
6. **低成本版本**：保留玩家承诺和关键决定，替换昂贵演出、唯一资产或新系统；同时写明体验损失。

若两种方案在玩家行动、信息结构或制作代价上没有实质差异，不要包装成不同方向。只有核心承诺、关键机制、持久后果或制作范围的选择会显著改变成品时，才停下来请求用户决定。用户明确要求完整草案或自动出稿时，直接选择有依据的方案展开，并集中列出代替用户作出的假设。

## 任务的内容定位

写明任务对游戏的贡献：角色关系、区域认知、主线推进、机制学习或成长资源。指定主要贡献和可观察结果，例如“玩家能根据两位证人的矛盾判断谁隐瞒了运输路线”，而不只写“增强沉浸感”。

区分接取吸引力、推进动机与结束回报。金钱可以支持接取，但不自动解释为何玩家持续关心角色。奖励同时考虑资源、信息、关系、世界变化和玩法权限；数值需对齐项目经济与成长曲线，无数据时只定义奖励意图。

为任务说明可进入时期、预计参与者能力与前置知识。高等级玩家、晚接取者或已知真相的玩家若仍能接取，应有合理入口或差异反应；没有动态适配能力就控制适用范围。

## 让玩家完成关键行动

从“玩家要体验什么”反推可操作行为：

| 体验目的 | 行为设计问题 | 常见失效 |
|---|---|---|
| 调查与推理 | 证据如何获得、解释、交叉验证，何时足以行动 | 跟标记收集，NPC 直接揭晓全部答案 |
| 角色关系 | 玩家如何通过行动兑现或违背承诺 | 好感只靠一次无代价对话选项 |
| 探索与发现 | 环境提供何种线索，玩家如何确认猜测 | 未发现线索就显示终点精确标记 |
| 道德或利益冲突 | 决策者知道什么，代价由谁承担 | 一个选项显然在所有维度占优，却被包装成两难 |
| 成长与教学 | 新机制是否在安全条件下尝试，再在变化情境中运用 | 只有说明文本，没有应用机会 |

线性任务也应有行动和反馈的因果关系。NPC 可承担剧情关键行动，但应明确玩家贡献；不要自动将所有高潮变成玩家战斗。

调查任务区分“关键事实”和“发现途径”。项目允许时，为关键事实提供不同获得方式；否则安排可理解的补救路径。不要为了稳健机械增加固定数量的线索。

## 选择与分支预算

为选择记录：决策前信息、选项及代价、即时反馈、持久变化、后续响应、资源差异与测试差异。表达立场而不改结局的选择可以成立，需兑现对应角色反馈。

允许分支回到共同主线，但检查所保留的身份、承诺、物品或阵营差异是否还影响后续反应。不要在汇合处悄悄抹除已承诺的后果。

用“新增独立场景、角色状态、对白变体、唯一资产、待验证组合”比较方案成本。对白节点数量不能单独代表制作成本。不将分支组合数简单相乘为实际测试数量，先识别互斥和不可达组合。

## 失败、节奏与结尾

区分玩法失败、叙事失败、任务取消和暂时中断。玩家失败后可转入有代价的后续方案，但需保证任务目的与叙事因果仍成立；不可默认所有失败都必须继续推进。

节奏按信息、决策、操作压力和情绪负荷观察。移动或安静段可以承接情绪、观察环境与消化信息；压缩前确认其作用。时长估计分成移动、操作、对话与演出，并注明依据。

结束应有完成反馈、结算与世界反应；任务链还需说明下一阶段的吸引力。让玩家能辨认自己的行动改变了什么。

## 设计交付

完整设计增加一份简短的“设计决定与取舍”：关键选择、依据、放弃方案、制作代价和验证方式。只写影响任务的决定，避免把推导过程全部输出。
