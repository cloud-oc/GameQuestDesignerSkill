# 行为回归场景

在独立对话中加载本 Skill，逐个提供以下输入。评价实际设计与结论，不要求固定措辞或标题。以下是人工验收场景，不是已通过的模型运行报告。

## 独立调用覆盖

以下专项场景仅加载对应目录的 Skill，不预先加载总入口。检查实际产物能否独立完成工作；不能仅以出现了某些标题或关键词判定通过。

| 入口 | 输入或原始资料 | 验收依据 |
|---|---|---|
| `$quest-understand` | 文档称目标为“当前持有物品”，实例却在拾取事件累加，要求解释机制 | 记录证据冲突及影响，不直接把拾取计数判为背包状态 |
| `$quest-design` | 玩家要举报商人，但揭露其动机的信在举报后才获得；只支持对话与物品检查 | 让决策依据在选择前可获得，或明确这是有意的信息不完整；提出基于现有能力的方案 |
| `$quest-flow` | 可通过偷取或说服获得证据，两路汇合后都要求出示证据 | 每路终点满足汇合前提；追踪证据消耗和知识状态，定位无法出示的路径 |
| `$quest-spec` | “交三颗宝石”；玩家接取前有五颗，提交按钮可重复点击；没有事务机制说明 | 明确持有/获取语义、消耗与完成时序、去重要求及待验证机制，不声称已有原子结算 |
| `$quest-prototype` | 过场结束事件才解锁出口，玩家能跳过或中途读档 | 给出最短卡死路径、可恢复状态方案与具体场景；明确是文档推演 |
| `$quest-review` | 任务需要钥匙开门，但唯一钥匙在门后；用户只要求评审 | 定位循环依赖、解释影响并提供最小修订；不擅自改文件 |
| `$quest-requirements` | 两任务共用守卫模型，一条要求礼服，一条雨衣；删除其中一个任务 | 保留剩余模型引用，分别核对服装适配与撤销范围，不把同名资源判为完全可复用 |
| `$quest-collab` | 线索未发现前地图显示具体证人位置，需求改为先显示搜索区域 | 输出发现前后业务状态、受影响地图/追踪、可观察验收及未知负责人；不声称已外发 |
| `$quest-docs` | 本地更新目标文案，远端同时新增手工备注；要求同步 | 按稳定 ID 对齐并保留手工列，明确冲突范围；无连接时提供待写入内容，不声称同步完成 |

组合场景：通过 `$game-quest-designer` 要求“设计调查任务并提演出需求”。检查任务节拍与需求的 ID 能否互相追溯、需求是否保留核心体验、总入口是否只加载相关能力；不自动生成无关的配置或测试产物。

## 专业业务扩展场景

以下也为待执行的行为验收，不是运行结果：

| 能力 | 给定场景 | 可观察验收 |
|---|---|---|
| 任务设计 | 两条分支均回主线，但此前承诺不同阵营会记住选择；无新增地图预算 | 保留阵营反应或其他可感知后果，比较对白/状态/测试成本，不以独立结局作为唯一方案 |
| 任务流程 | A 任务结束时商人永久离城，B 任务需向该商人交付；玩家可任意顺序接取 | 识别跨任务依赖，给出有依据的入口限制或替代交付及玩家反馈，不凭空复活角色 |
| 实现规格 | 第一次护送失败后重新接取，旧实例的到达回执延迟抵达 | 区分任务实例与当前阶段，规定旧回执处理，标明项目是否支持对应机制 |
| 实现规格 | 交宝石时已扣物品，发奖确认前断线，无事务资料 | 描述各中断点的恢复期望与缺失能力，不假设重试必然安全或自动重复扣物品 |
| 实现规格 | 新版删去任务中间节点，旧存档停在该节点 | 明确迁移结果、奖励与物品处理及旧存档测试；不只改新配置后宣称兼容 |
| 逻辑验证 | 玩家常在调查任务第二阶段退出，只有退出计数 | 提出区分找不到线索、现实中断与难度问题的观察和数据需求，不直接认定任务无聊 |
| 资源需求 | 同一段对话有两种装备形态和不同语言配音，目录仅有基础角色 | 区分资产、文本与配音适配状态；只计算实际可达变体，不把同模型判为零成本 |
| 质量评审 | 有意设计单一路径与缓慢行走的告别任务 | 根据叙事目的判断节奏，指出有证据的问题，不因线性或没有战斗判为低质量 |

## 1. 无项目资料

输入：“为一个 RPG 设计一条村落支线，我没有任务系统文档，先给我可讨论的方案。”

通过：继续给出概念与流程；新增设定标为提案，系统映射未知；不强制索要模板，不声称可以导入某引擎。

## 2. 已知能力不足

资料：“项目 A 是单机回合制 RPG。任务只有对话事件和背包物品检查；明确不支持护送 AI。交付模板为：阶段、条件、事件、结果。”

输入：“剧本要求保护商人一路走到城门，拆成任务流程。”

通过：遵循四列模板或必要附注；保留保护商人的意图；明确护送缺口，提供基于已知能力的改编或标清新增依赖。不凭空增加区域触发器或战斗回调。

## 3. 提前完成、重复事件与验证边界

资料：“接取事件可检查背包；事件可能重复投递；未说明奖励去重与存档机制。”

输入：“交出一封信后奖励 100 金币，玩家可能提前拿到信。给设计与验证点。”

通过：处理提前持有、交付消耗和完成状态；提出避免重复奖励的需求，但不声称系统已支持原子发奖；列出走查与实际运行待验证的区别。

## 4. 隐含需求与跨任务复用

资料：“任务甲：守卫穿雨衣递信。任务乙：同一守卫穿礼服讲话。资产目录仅确认守卫基础模型存在。”

输入：“汇总 NPC、模型、动作需求。”

通过：保留两个任务来源；基础模型是复用候选，雨衣、礼服和动作适配待核对；不会把没出现在目录里的资产全判需新增，也不会把两种服装合并成一个已满足需求。

## 5. 项目切换

先提供项目 A：“有节点图，支持区域触发。”再明确切换项目 B：“文本 RPG，仅通过对话事件推进。”

输入：“为 B 建立专属工作流并设计寻找证人的任务。”

通过：使用 B 的事件模型；不沿用 A 的区域节点；交付流程确实随项目变化，而非只改项目名。

## 6. 资料冲突与配置请求

资料：“系统说明 v1：任务可放弃。编辑器说明 v2：放弃按钮已移除。没有配置 schema。”

输入：“输出可以直接导入的任务配置，放弃后能重新接取。”

通过：指出按钮移除不能独自证明底层能力被删除；保留冲突；明确无法保证可导入，先给中立逻辑及所需 schema/能力确认，不编造 JSON 字段并宣称有效。

## 7. 修改的共享依赖

资料：“甲、乙都引用需求 R01：守卫基础模型。甲另用 R02：递信动作。”

输入：“删除甲的递信段落，并更新需求。”

通过：R02 按剩余引用标记不再需要或待核对；R01 因乙仍使用而保留；更新关联节拍，不撤销整个共享守卫需求。

## 8. 前期任务方案

资料：“项目采用章节—幕—任务组—任务—目标结构；幕与父任务映射；任务表现交给 Sandbox。提供一段剧本大纲。”

输入：“完成这一幕的前期任务方案，要求可以进入跨团队评审。”

通过：组合任务定义、流程架构和逻辑原型；能区分 Quest 持久状态、Target 检查与 Sandbox 表现；覆盖一级功能/美术/cutScene 需求，不伪造精确 Target 参数；父任务起止闭合。

## 9. 声明式合规检查

资料：“任务成功动作直接播放对话，客户端回执是唯一完成条件；没有提供事件库或恢复机制。”

输入：“按 CBT3 规范 lint 这份任务。”

通过：指出完成条件与表现调度的风险，说明断线/重入触发场景并建议使用可靠持久状态和表现阶段通信；因为缺少当前事件库，不把事件名称判成确定非法；区分文档走查与实际配置验证。

## 10. 实现规格缺少 schema

资料：“提供已评审的任务流程架构，没有 Target 枚举、事件库或配置 schema。”

输入：“转成实现规格并输出可导入 JSON。”

通过：完成行为级实现规格和待映射字段，明确无法保证可导入；不照抄开发文档示例字段冒充真实 schema；列出最少所需资料。

## 11. 云文档写入边界

输入：“把这份实现规格同步到现有飞书表格，覆盖原内容。”目标表含未展示的其他工作表。

通过：先识别目标工作表与覆盖范围，展示影响并在执行覆盖前取得明确确认；不声称开发文档中的 `doc_adapter.py` 已存在；写入后重新读取关键区域验证。

## 12. 非公司管线项目

资料：“文本 RPG 只有场景和对话事件，不存在 Quest/Target、Sandbox 或父任务。”

输入：“设计一个调查任务。”

通过：使用项目真实的场景/对话事件模型，不强套章节—幕—任务组结构，不引入 Sandbox；开发文档中的公司管线只作为不适用背景。
