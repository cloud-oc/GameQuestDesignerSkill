01

安装 Skill

在终端运行下面的命令，安装器会查找支持的 Agent 目录。

npx --yes --package=game-quest-designer-skills@latest -- game-quest-designer-skills install
02

说说你的任务

带上背景、想让玩家体验的内容，以及已有资料。

用 $game-quest-designer 设计一条港口失踪案支线。希望玩家自己找线索，场景尽量复用。资料不够的地方先写成假设。
03

继续打磨

想改哪部分，就直接点名对应的 Skill。

用 $quest-prototype 检查这份流程：如果玩家提前拿到账本，或者调查到一半读档，任务还能继续吗？

按眼前的问题选一个 Skill

拿不准时，用 $game-quest-designer 描述需求，它会选用合适的方法。

总入口

从你的问题开始，安排这次需要的设计工作。

$game-quest-designer

了解项目

读系统说明和已有任务，整理哪些做法能用、哪些还要确认。

$quest-understand

构思任务

想清人物的麻烦、玩家的动机，以及值得亲自参与的行动。

$quest-design

安排流程

把故事拆成玩家能走过的步骤，写清分支与结尾。

$quest-flow

写清实现规则

说明触发条件、任务状态和完成判定，方便程序实现。

$quest-spec

检查任务逻辑

走一遍正常和意外情况，找出任务会卡住的地方。

$quest-prototype

整理制作需求

列出需要的场景、角色、对白和演出，注明用途与检查方式。

$quest-requirements

准备团队交接

整理程序、关卡、美术与界面团队各自需要的信息。

$quest-collab

评审与修改

指出具体场景中的问题，说明影响，并给出修改建议。

$quest-review

整理任务文档

读取、修改或同步文档，保留来源和版本差异。

$quest-docs

让玩家查出真相，而不只是追着标记走。

  • 01

    发现矛盾货单写着运往北岸，船工却说船往南走。新线索让玩家能继续追问。

  • 02

护送的存档规则还不清楚，草案先用“约定会合”。以上是设计示例，不代表你的项目已经支持这些功能。

写成团队拿得到、看得懂的文档

只整理当前需要的部分。先讲清玩法，再补充编号、条件与制作细节。

任务简报

故事是什么，玩家为什么参与，结束时改变什么。

任务流程

每一步的目标、行动、反馈，以及分支怎么汇合。

实现规格

怎样触发和完成，失败或读档后怎样继续。

制作需求

需要哪些资源，能复用哪些内容，怎样验收。

评审记录

哪里有问题，什么情况下出现，如何修改和复查。

文档多了，也能检查有没有漏项

开始之前，你可能想问

必须先整理全部项目规则吗？+

不用。小任务可以直接开始，资料不足的部分先写成假设。新项目或多人协作时，再把影响设计的规则整理下来。

能直接生成引擎配置吗？+

需要你提供真实配置格式、项目约定和可用工具。没有这些资料时，先输出供团队讨论和实现的规格文档。

会把每条任务都写成同一个模板吗？+

任务从人物矛盾和玩家行动开始设计。模板用来检查有没有遗漏；线性任务不必硬加分支，小创意也不需要填完整表格。

支持哪些语言？+

网站提供中文、英文和日文。Skill 默认跟随你的交流语言；项目字段名、ID 和 API 名称保持原样。
