Take a missing-person quest at a harbor

The same story plays differently depending on the mechanics available. A few project rules make the choices clearer.

Known rules of this fictional project

Available actions
Observe, talk, trade and sneak
Clue tracking
Record each clue the player discovers
Character limits
Key NPCs cannot die permanently
Still unknown
How cross-map escorts resume after loading
Draft budget
Reuse the harbor at night and 3 existing NPCs

Let players uncover the truth, not just follow markers.

  • 01

    Find a contradictionThe manifest says north shore, but a dockworker saw the boat head south. This clue opens a new question.

  • 02

    Choose how to investigateTrade or sneak to get the ledger. Both routes meet at the warehouse, limiting extra locations.

  • 03

    Make the choice matterThe player decides whether to protect the dockworker. Later reactions remember that choice, even on a shared story path.

Escort save rules are still unknown, so the draft uses an agreed meeting point. These are design examples, not claims about features in your project.

Documents your team can work from

Write only what you need right now. Explain the play first, then add identifiers, conditions and production details.

Quest brief

The story, why the player gets involved, and what changes by the end.

Quest flow

Goals, actions and feedback at each step, including where branches meet.

Implementation spec

Triggers, completion rules, failure handling and save recovery.

Production needs

Required assets, opportunities to reuse them, and acceptance checks.

Review notes

What goes wrong, when it happens, how to fix it and how to check again.

Catch missing links as the documents grow

The optional quest-package.json links quests, steps, requirements and tests. Its validator finds duplicate IDs, broken references and unreachable nodes. It does not replace engine testing and is not engine configuration.

quest-package-validate
npx --yes --package=game-quest-designer-skills@latest \
  -- quest-package-validate ./quest-package.json

A few things you might want to know

Do I need to document every project rule first?+

No. Start a small task right away and mark missing details as assumptions. For a new project or team collaboration, collect the rules that affect the design.

Can it generate engine configuration directly?+

It needs your real configuration format, project conventions and available tools. Without those, it writes specifications for your team to discuss and implement.

Will every quest follow the same template?+

Design starts with character conflicts and player actions. Templates help catch omissions. Linear quests do not need forced branches, and a small idea does not need a full set of tables.

Which languages are supported?+

The website is available in Chinese, English and Japanese. Skills follow the language you use, while project field names, IDs and API names stay unchanged.
