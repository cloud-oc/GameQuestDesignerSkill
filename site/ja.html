完成した脚本でも、思いついたばかりのアイデアでも大丈夫です。まずは草案を作り、少しずつ具体化します。

01

Skill をインストール

以下のコマンドをターミナルで実行します。対応する Agent の保存先を探してインストールします。

npx --yes --package=game-quest-designer-skills@latest -- game-quest-designer-skills install
02

クエストを伝える

舞台設定、プレイヤーに体験してほしいこと、手元の資料を共有します。

$game-quest-designer で港の失踪事件を扱うサブクエストを作ってください。プレイヤー自身が手がかりを探し、既存の場所をできるだけ使う案にしたいです。不明点は仮定としてまとめてください。
03

気になる部分を詰める

作業に合う Skill を指定して、続きを進めます。

$quest-prototype でこの流れを確認してください。帳簿を先に見つけた場合や、調査の途中でロードした場合も進められますか？

今やりたいことから Skill を選ぶ

迷ったら $game-quest-designer に相談してください。依頼に合う方法を選んで進めます。

総合窓口

相談内容に合わせて、必要な設計作業を進めます。

$game-quest-designer

プロジェクトを理解する

仕様書と既存クエストを読み、使える機能と確認が必要な点を整理します。

$quest-understand

クエストを考える

人物の悩み、プレイヤーの動機、自分で関わりたくなる行動を考えます。

$quest-design

流れを組み立てる

物語を遊べる手順に分け、分岐と結末を整理します。

$quest-flow

実装ルールを書く

開始条件、進行状態、完了の判定を開発者に伝わる形にします。

$quest-spec

ロジックを確かめる

通常の進め方と想定外の行動を確認し、進行不能になる箇所を探します。

$quest-prototype

制作内容をまとめる

必要な場所、人物、会話、演出と、その用途や確認方法を整理します。

$quest-requirements

チームへ引き継ぐ

プログラム、レベルデザイン、アート、UI の各担当に必要な情報をまとめます。

$quest-collab

レビューして直す

具体的な場面から問題と影響を説明し、修正案を出します。

$quest-review

資料を整理する

出典と版の違いを残しながら、資料の読み取り、編集、同期を行います。

$quest-docs

たとえば、港の失踪事件なら

同じ物語でも、使える仕組みによって遊び方は変わります。まずは設計に関わるルールをいくつか整理します。

架空のプロジェクトの条件

使える行動
観察、会話、交換、潜入
手がかりの記録
発見した手がかりを個別に記録
人物の制約
重要な NPC は永久に死亡しない
未確認の仕様
マップをまたぐ護衛のロード後の再開
草案の制作範囲
夜の港と既存 NPC 3 人を再利用

マーカーを追うだけでなく、自分で真相を探る。

  • 01

    矛盾に気づく積荷目録には北岸行きとあるのに、港の作業員は船が南へ向かったと言う。手がかりを得ると、新たな質問ができる。

  • 02

    調べ方を選ぶ交換か潜入で帳簿を手に入れる。どちらの経路も倉庫で合流し、新規の場所を増やしすぎない。

  • 03

    選択の結果を残す作業員を守るかどうかを選ぶ。同じ本筋に戻っても、その後の人物の反応は選択に応じて変わる。

護衛のセーブ仕様は未確認なので、草案では「待ち合わせ」にします。これは設計例であり、あなたのプロジェクトで利用できる機能を示すものではありません。

チームが読んで制作に使える資料へ

今必要な部分だけをまとめます。まず遊び方を説明し、その後に ID、条件、制作の詳細を添えます。

クエスト概要

どんな物語で、なぜ関わり、最後に何が変わるのか。

進行フロー

各段階の目標、行動、反応と、分岐の合流先。

実装仕様

開始と完了の条件、失敗時の処理、ロード後の再開方法。

制作要件

必要な素材、再利用できるもの、完成を確認する方法。

レビュー記録

問題が起こる場面と影響、修正案、再確認の方法。

資料が増えたら、参照の漏れも確認

任意の quest-package.json でクエスト、手順、制作要件、テストを関連づけられます。検証ツールは ID の重複、参照切れ、到達できないノードを検出します。エンジンの設定ファイルではなく、実機テストの代わりにもなりません。

quest-package-validate
npx --yes --package=game-quest-designer-skills@latest \
  -- quest-package-validate ./quest-package.json

使い始める前によくある質問

先にすべての仕様を整理する必要がありますか？+

いいえ。小さな作業ならすぐに始め、不足している情報は仮定として残せます。新しいプロジェクトや共同作業では、設計に関わるルールを整理すると役立ちます。

エンジン用の設定を直接生成できますか？+

実際の設定形式、プロジェクトの規約、利用可能なツールが必要です。資料がない場合は、チームで検討・実装するための仕様書を作ります。

どのクエストも同じ型になりませんか？+

人物の対立やプレイヤーの行動から考えます。テンプレートは見落としを防ぐためのものです。一本道に無理に分岐を加えたり、小さな案に大量の表を求めたりはしません。

どの言語に対応していますか？+

サイトは中国語、英語、日本語に対応しています。Skill はユーザーの言語に合わせて回答し、プロジェクトのフィールド名、ID、API 名はそのまま扱います。
