# 任务文档操作

## 工作约定
这是可独立使用的游戏任务设计能力。先复用当前项目资料和用户模板；没有资料时可交付标明假设的方案。保留来源与稳定 ID，区分事实、推导、建议和未知。不把其他项目的能力或资产当成本项目事实。
按用户要求的范围交付；涉及机器配置须有真实格式依据。未运行引擎、未读取资产库或未写入远端时，准确说明验证范围。默认使用“任务定义、流程架构、实现规格、逻辑原型、质量验证”等通用术语。

## 资料读取
识别本地/远端资源类型、子表或文档范围、真实工具能力和用户指定目标。先读取内容与元信息，不能只看标题推断任务规则。
有分页、嵌入表格或附件时，按本次范围补全读取；无法访问的部分明确记录，避免把局部内容当全文。
## 更新与同步
维护设计到实现的对应关系：任务/节拍 ID、规则 ID、配置引用、文本/资源 ID 与测试 ID。只保留实际使用的层级，避免新增一套与项目既有 ID 冲突的编号。
修改条件、目标或结局时，查找受影响的文案、资源需求与测试记录；变更日志说明旧值、新值、原因和待同步位置。同步完成不代表这些业务内容已经由相应团队验收。
把任务 ID、节点 ID、需求 ID 当作关联键；行号和标题可能变化，不应单独作为更新依据。
明确新增、更新和保留区域，沿用用户模板、公式与手工列。空值、未知与删除意图分开；不因新资料没提到就删除旧记录。
检查本地与远端版本；双方变化时给出差异并保留冲突。已有授权覆盖明确目标时直接执行，范围或冲突无法确定时再请求选择。
首次写入前生成可核对内容；写后重新读取关键字段和关联引用。部分失败时报告成功/失败项，重试前检查已写入结果，避免重复创建。
## 交付
报告读取与更新的确切范围、输出路径或真实链接、验证结果和剩余冲突。
无连接或权限时交付本地内容和待写入范围，不声称云端同步完成。不要把同步设计文档误当成修改线上游戏状态或核心配置表。
