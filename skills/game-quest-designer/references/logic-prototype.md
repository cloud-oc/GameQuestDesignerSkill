# 逻辑原型

逻辑原型用于验证任务结构、状态流和异常恢复，不承担最终表现制作。

从流程架构或实现规格中提取任务组、Quest、Target、条件、状态事件及它们的连接。至少标出：任务入口、任务启动、目标完成、任务成功/失败、后续解锁和任务链终点。

每条连接注明：

`来源状态/节点 → 条件或事件 → 目标状态/节点 → 依据或待确认`

用不同标记区分：持久任务状态、检查条件、外部表现阶段、玩家可见目标。不要把对话播放、NPC 移动或镜头当成任务已完成的充分证据，除非项目明确提供可靠回执和恢复机制。

走查顺序：正常路径 → 提前满足 → 重复事件 → 离开/重入或读档 → 失败/取消 → 最终汇合。发现缺口时记录触发场景、卡住的状态、期望恢复点和责任层。

用户要可视化时，先给出节点与边的中立结构，再用当前环境真实可用的图表或画板工具创建；不能创建时交付 Mermaid 或文本结构，并明确未写入外部系统。
