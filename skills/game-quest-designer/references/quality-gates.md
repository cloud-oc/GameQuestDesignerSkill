# 质量门禁

只检查与本次产物相关的项目，不把清单原样倾倒给用户。

## 依据

- 使用了哪些项目资料、版本和模板？关键结论能否追到来源？
- 资料明确、推导、建议、待确认是否分开？冲突是否被保留？
- 是否把未知能力、枚举、资源或团队规则写成事实？

## 设计

- 剧情因果 → 玩家信息与行动 → 系统条件和结果是否可追溯？
- 每个主要路径是否从合法入口到合法终态？目标文案与实际完成条件是否一致？
- 声明式项目中，持久状态与表现调度是否分层？
- 关键的提前完成、重复事件、重入/读档与失败恢复是否有设计目标或待验证点？

## 制作与变更

- 隐含制作需求是否有来源，供给状态是否与需求依据分开？
- 共享依赖是否保留全部引用？修改是否同步影响的逻辑、资源、文案和验证点？
- 是否承诺了没有依据的工期、预算、负责人或资产可用性？

## 验证与交付

- 文档走查、schema/配置验证、引擎运行验证是否准确区分？
- “可导入”“已同步”“运行通过”是否有真实工具结果支持？
- 写入是否在授权范围内，覆盖/批量/删除等操作是否已确认并复核？
