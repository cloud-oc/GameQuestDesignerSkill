# 跨管线交付

跨管线材料要让接收方知道“为什么、在哪里、要达到什么状态、谁还需确认”，不替接收方虚构实现方案或排期。

## 演出需求

从实现规格和任务节拍提取演出名称、来源任务/节拍、叙事目的、玩家可控边界、前后状态、场景与角色、参考、等级、所需资源和验收点。等级、工期与负责人仅在项目资料明确时填写。

把“需要表现某结果”与“必须使用某种 Timeline/镜头”分开；后者若未确认，标为实现建议。提交、拉群、@负责人等外部动作仅在用户要求且工具可用时执行。

## UED 需求说明

建议回答：

1. 改了什么：任务类型、目标、状态、线索或触发/完成条件。
2. 为什么改：规则、剧情表达、体验或版本原因。
3. 玩家在每一状态看到什么、理解什么、下一步做什么。
4. 影响哪些场景：任务手册、地图、HUD、线索、新手引导等。
5. 必须本版本完成与可后置范围。
6. 由策划确认的配置、剧情、文本和状态规则。
7. 占位文案、配置表、原型或来源链接。

## 变更交接

保留需求 ID 与所有来源。任务修改后把需求标为新增、变更、沿用或不再需要；共享依赖只有在全部引用消失后才建议撤销。交付中明确待谁确认，但没有组织资料时不擅自指定岗位或审批链。
