# 虚构项目契约示例：《雾港来信》

本例只演示契约如何改变设计决策，不代表通用 RPG 标准。

## 项目摘要

- `已确认`：单机区域型叙事 RPG；任务侧重调查、关系与有限战斗。
- `已确认`：玩家可检查场景物、询问角色、对证词作二选一追问；不支持自由输入推理。
- `明确不支持`：护送 AI、动态昼夜和任意 NPC 日程。
- `未知`：奖励结算是否具备事务或幂等机制，因此实现规格不得宣称重复请求安全。

## 关键约定

| 规则 ID | 结论 | 状态 | 设计影响 |
|---|---|---|---|
| PC-01 | 任务层级为任务→阶段→目标 | 已确认 | 不创建任务组或父任务 |
| PC-02 | 关键事实写入线索册，可重复查看 | 已确认 | 调查结论不能只存在于一次性对白 |
| PC-03 | 地图只显示搜索区域；检查过线索后才显示对象 | 已确认 | 不用精确标记替代调查 |
| PC-04 | 分支只允许局部关系和后续对白差异 | 已确认 | 不承诺独立结局或永久世界分叉 |
| PC-05 | 任务状态存档，当前对白与 NPC 朝向不存档 | 已确认 | 重入时按阶段重建表现，不等待对白结束事件 |
| PC-06 | 每个支线最多新增一个小型场景变体 | 临时建议 | 优先复用雾港、仓库和已有角色 |

## 同一题材如何被契约改变

题材：“保护信使把证据带到议会。”

- 不能设计实时跟随信使穿城，因为项目明确不支持护送 AI。
- 可改为玩家先调查安全路线，在两处风险点做处理，再触发信使离场；任务以持久阶段和路线处理结果推进。
- 信使离场演出被跳过或读档后，任务根据“路线已处理、信件已托付”恢复，而不是依赖演出结束回执。
- 玩家最终选择公开或隐瞒证据时，只承诺关系与后续对白差异，不承诺两套城市世界状态。

这说明项目契约必须改变玩家行动、系统映射和制作范围；只替换项目名不算适配。
